### Key Rules
1. ALL unit tests live inside `src/<module>/` co-located with source files as `*.spec.ts` — NEVER inside `test/`
2. ALL integration tests live in `test/integration/<module>/` as `*.integration-spec.ts`
3. ALL E2E tests live in `test/e2e/` as `*.e2e-spec.ts`
4. Mock factories go in `test/mocks/services.mock.ts` — extend the existing file, do NOT create new mock files
5. Test fixtures go in `test/fixtures/<module>.fixture.ts`
6. E2E helper providers go in `test/helpers/e2e-providers.helper.ts` — extend it for new modules

## Testing Patterns & Conventions (MUST follow)

### 1. Unit Test Pattern (co-located in src/)

Every unit test uses `Test.createTestingModule` with mock providers:

```typescript
import { Test, TestingModule } from '@nestjs/testing';
import { SomeService } from './some.service';
import { DepService } from 'src/dep/dep.service';
import { mockDepService } from '../../../test/mocks/services.mock';

describe('SomeService', () => {
  let service: SomeService;
  let depService: ReturnType<typeof mockDepService>;

  beforeEach(async () => {
    jest.clearAllMocks();
    depService = mockDepService();

    const module: TestingModule = await Test.createTestingModule({
      providers: [
        SomeService,
        { provide: DepService, useValue: depService },
      ],
    }).compile();

    service = module.get(SomeService);
  });

  afterEach(() => jest.clearAllMocks());

  describe('methodName', () => {
    it('happy path description', async () => {
      depService.someMethod.mockResolvedValueOnce({ _id: '1' });
      const result = await service.methodName('input');
      expect(result.success).toBe(true);
      expect(depService.someMethod).toHaveBeenCalledWith('input');
    });

    it('returns not found when ...', async () => {
      depService.someMethod.mockResolvedValueOnce(null);
      const result = await service.methodName('input');
      expect(result.code).toBe(HttpStatus.NOT_FOUND);
    });

    it('returns handleError on exception', async () => {
      depService.someMethod.mockRejectedValueOnce(new Error('boom'));
      const result = await service.methodName('input');
      expect(result.success).toBe(false);
    });
  });
});
```

### 2. Mock Factory Pattern (test/mocks/services.mock.ts)

All mock factories return fresh jest.fn() maps. Extend the EXISTING file:

```typescript
export const mockNewService = () => ({
  find: jest.fn().mockResolvedValue([]),
  findById: jest.fn(),
  findOne: jest.fn(),
  create: jest.fn(),
  updateOne: jest.fn().mockResolvedValue({ modifiedCount: 1 }),
  updateMany: jest.fn().mockResolvedValue({ modifiedCount: 1 }),
  deleteOne: jest.fn().mockResolvedValue({ deletedCount: 1 }),
  deleteMany: jest.fn().mockResolvedValue({ deletedCount: 1 }),
});
```

### 3. Fixture Pattern (test/fixtures/<module>.fixture.ts)

Use STRING IDs (not Types.ObjectId) for _id and all references to avoid mongoose type errors:

```typescript
export const sampleSomeDoc = (overrides: Partial<any> = {}) => ({
  _id: '64f1a2b3c4d5e6f7a8b9c0d1',     // STRING, not ObjectId
  name: 'Default Name',
  // ... all default fields
  ...overrides,
});

export const roleUser = (overrides: Partial<any> = {}) => ({
  _id: '64f1a2b3c4d5e6f7a8b9c0d5',
  role: 'director',
  ...overrides,
});
```

### 4. tokenToUser Mocking

Services call `tokenToUser(context, secret)` from `src/utils/helper`. Mock it via:

```typescript
import * as helperModule from 'src/utils/helper';
jest.mock('src/utils/helper');

// In test:
(helperModule.tokenToUser as jest.Mock).mockReturnValueOnce({ _id: 'user-id', passcode: null });
```

### 5. AppResponse — NEVER mock it

`AppResponse` is a static helper that returns structured objects. Assert the shape:

```typescript
// AppResponse.notFound('Event') returns: { code: 404, success: false, message: 'No such Event exists!' }
// AppResponse.unauthorized() returns: { code: 401, success: false, message: '...' }
// AppResponse.handleError(err) returns: { code: 500, success: false, message: '...' }

expect(result.success).toBe(false);
expect(result.code).toBe(HttpStatus.NOT_FOUND);
expect(result.message).toMatch(/Event/i);
```

### 6. Integration Test Pattern (test/integration/<module>/)

Uses real MongoDB (in-memory via mongodb-memory-server), real Mongoose models, real service. NO service mocks.

```typescript
import { startMongoMemoryServer, stopMongoMemoryServer } from 'test/helpers';

describe('SomeService (integration)', () => {
  let module: TestingModule;
  let service: SomeService;
  let model: Model<Some>;
  let uri: string;

  beforeAll(async () => {
    uri = await startMongoMemoryServer();
    module = await Test.createTestingModule({
      imports: [
        MongooseModule.forRoot(uri),
        MongooseModule.forFeature([{ name: Some.name, schema: SomeSchema }]),
      ],
      providers: [SomeService],
    }).compile();
    service = module.get(SomeService);
    model = module.get(getModelToken(Some.name));
  });

  afterAll(async () => { await module.close(); await stopMongoMemoryServer(); });
  afterEach(async () => { await model.deleteMany({}); });

  // Use `as any` for filter objects — mongoose's FilterQuery is overly strict
  // Use string IDs in fixtures — Types.ObjectId causes type errors with model.create()
});
```

### 7. E2E Test Pattern (test/e2e/)

Full HTTP → GraphQL → Resolver → Service → DB round-trip. Real GraphQL endpoint, real Mongoose, mocked external services, overridden guards.

```typescript
jest.mock('src/utils/helper', () => ({
  ...jest.requireActual('src/utils/helper'),
  tokenToUser: jest.fn(),
}));
import { tokenToUser } from 'src/utils/helper';
const mockedTokenToUser = tokenToUser as jest.MockedFunction<typeof tokenToUser>;

describe('SomeModule (e2e)', () => {
  beforeAll(async () => {
    process.env.JWT_SECRET = 'test-jwt-secret';
    uri = await startMongoMemoryServer();

    const moduleFixture = await Test.createTestingModule({
      imports: [
        ConfigModule.forRoot({ isGlobal: true }),
        MongooseModule.forRoot(uri),
        MongooseModule.forFeature([{ name: Some.name, schema: SomeSchema }]),
        GraphQLModule.forRoot<ApolloDriverConfig>({
          driver: ApolloDriver,
          autoSchemaFile: true,
          playground: false,
        }),
      ],
      providers: [Resolver, Queries, Mutations, Fields, Helpers, Service, ...getE2EMockProviders()],
    })
      .overrideGuard(JwtAuthGuard)
      .useValue({ canActivate: () => true })
      .overrideGuard(RolesGuard)
      .useValue({ canActivate: () => true })
      .compile();

    app = moduleFixture.createNestApplication();
    await app.init();
  });

  // Helper for GraphQL requests:
  const gql = (query, variables = {}, token?) => {
    const req = request(app.getHttpServer()).post('/graphql').send({ query, variables });
    if (token) req.set('Authorization', `Bearer ${token}`);
    return req;
  };
});
```

### 8. Test Naming Conventions
- Unit test files: `<filename>.spec.ts` (e.g., `event.mutations.spec.ts`)
- Integration test files: `<service>.service.integration-spec.ts`
- E2E test files: `<module>.e2e-spec.ts`
- Mock factory functions: `mock<ServiceName>()` (e.g., `mockEventService()`)
- Fixture functions: `sample<Type>Doc()`, `valid<InputName>Input()`, `<role>User()`

### 9. Test Case Structure (inside each describe block)
For every method, test:
1. Happy path (success response with correct HttpStatus code)
2. Unauthorized (no token / user not found)
3. Not found (resource doesn't exist)
4. Validation errors (missing required fields)
5. Exception handling (service throws → handleError response)
6. Edge cases (empty arrays, null optional args, boundary conditions)
